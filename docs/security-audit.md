审查日期：2026-11-14。源码基线：`7527244`。审查对象为本机已构建 APK，而非仅审查源 Manifest。

## 结论

在已检查的自有代码、合并 Manifest 和 APK 中，未发现 root、提权、写入系统分区、修改系统设置、安装/卸载其他 App 或删除外部文件的路径。没有发现可直接造成系统或其他 App 数据损坏的高危问题。正常 Android 沙箱环境下，可进行小范围人工安装测试。

这不是“绝对不会损伤手机”的保证，也不是渗透测试或安全认证。尚未测量真机温升、耗电、内存峰值和长期数据库写入量；当前测试包不应被视为已完成长期使用加固的正式版。

## 已核查的保护

| 检查 | 结果与依据 |
| --- | --- |
| 系统修改能力 | 自有代码无 shell/Runtime.exec/ProcessBuilder、root、设备管理、系统设置写入或系统分区访问；APK 未请求对应高权限。UsageStats 的调用仅查询使用记录。 |
| 外部文件与其他 App 数据 | 无共享存储/所有文件权限，无外部存储读写代码；删除语句只作用于本 App `traffic.db` 固定表。清空不接受外部路径。 |
| 网络与内容采集 | APK 无 INTERNET、录音、相机、通知读取、无障碍或屏幕捕获服务；消费事件类型采用白名单，不调用类名、快捷方式内容或 UI 内容接口。ACCESS_NETWORK_STATE 来自 WorkManager，仅用于网络状态，不等同于联网权限。 |
| 动态代码 / 原生组件 | 自有代码无动态加载；APK 包内未发现 `lib/`、`.so`、`.exe`、`.sh`。这不能替代对第三方 DEX 的完整审计。 |
| 组件暴露 | 首页必须导出以便启动，不解析外部 Intent 参数执行查询/删除；初始化 Provider 不导出；导出的 JobService 受 BIND_JOB_SERVICE 保护，诊断/Profile receiver 受 DUMP 保护；无导出的使用记录 Provider。 |
| 数据存放 | App 私有 SQLite，无上传、导出、世界可读文件或使用记录日志。allowBackup=false，云备份与设备迁移规则排除私有数据。数据库未单独应用层加密，不抵御 root/获授权调试环境。 |
| 写入一致性 | 会话、流向、游标和报表在同一事务提交；失败时回滚。清空只操作固定表，之后 VACUUM。启用 secure_delete，但不承诺闪存物理无痕擦除。 |
| 后台执行 | 唯一 24 小时周期任务，不使用精确闹钟、常驻轮询或前台服务；失败单轮最多重试 2 次，使用退避；设备不可交互时 Worker 直接退出。WAKE_LOCK 是 WorkManager 基础设施权限，不能据此承诺零耗电。 |
| 暂停与退出 | 暂停关闭动态接收器并取消已知唯一任务；清空同时关闭记录。卸载/撤权无需 root，不要求关闭系统安全功能。 |

## 发现与剩余风险

| 编号 / 等级 | 发现 | 影响与建议 |
| --- | --- | --- |
| S1 / 中：隐私 | 当前最终 Manifest 为 `debuggable=true`。 | 可调试包扩大对使用记录的访问面；例如拥有已授权 ADB/调试能力的主体。不是普通远程 App 可任意读取，也不意味着能修改系统。长期使用前应提供独立密钥签名且不可调试的正式包。不要向不信任的电脑授权 USB 调试。[官方说明](https://developer.android.com/privacy-and-security/risks/android-debuggable) |
| S2 / 中：资源稳定性 | 7 天是时间边界，尚无硬性 DB 容量、会话数量和单批处理量上限。每次 `Store.save()` 重写有效表，`buildReports()` 重算保留区间。 | 正常数据量下不等于手机损坏，但高事件量/频繁解锁会增加内存、CPU 和写入压力；可能导致本 App 卡顿、崩溃或额外耗电。正式长期运行前应增加容量/批次预算、刷新节流、增量更新及压力测试。 |
| S3 / 低：取消响应 | `SummaryWorker` 未将 `isStopped()` 传入 Collector；循环检查交互与授权，但不检查取消/暂停标记。 | 取消任务后，已经开始的同步可能仍运行到当前批结束，影响取消响应和资源消耗。查询结束时间在批开始时固定，因此不据此认定读取了暂停后新发生的事件。建议增加协作式取消检查和处理预算。 |
| S4 / 限制：保留策略 | 应用未执行时无法到期物理删除；SQLite 释放页可复用但文件不自动缩小。 | 不能把“7 天滚动”解释为到点擦除或文件大小硬上限。旧记录读取过滤、恢复后清理；清空做逻辑删除和 VACUUM，不保证闪存介质上不可恢复。 |
