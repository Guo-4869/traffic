# Traffic

Android 本地使用统计：记录 **App 名称、包名、进入 / 离开前台的时间**，展示每日使用情况和 App 之间的流动。Android 9（API 28）及以上，无联网权限、无广告、无前台服务、无无障碍服务。

## 当前功能

- 首次明确同意后，引导用户开启系统「使用情况访问权限」；不导入同意之前的历史。
- 同包 5 秒内重复会话合并；保留前台时间段，计算时长时不把短暂切走的时间计入。
- 按包维护前台状态，不读取或保存 Activity 类名，不调用隐藏 API。
- App 流向独立于会话合并：A → B → A 不会因为合并 A 的会话而丢失。
- 今日 / 近 7 天时长排行、打开次数、流向图、秒级时间线、日报与周报详情。
- 使用事件与聚合源数据只保留最近 7 × 24 小时；每次运行清理并重建报表，旧周报会随源数据过期变为不完整。
- 暂停记录、清空全部记录；关闭云备份与设备迁移。数据只存于 App 私有 SQLite。

## 安装和使用

1. 构建后安装 `dist/Traffic-0.1.0-debug.apk`（开发测试签名，不是正式发布包）。
2. 打开 App，点击「了解并开启记录」，阅读说明后同意。
3. 在系统设置中为 Traffic 开启「使用情况访问权限」，返回 App。
4. 正常使用几个其他 App，再回到 Traffic 点击「刷新统计」。最近 5 秒留到下次拉取确认。
5. 「概览」查看排行与流向，「时间线」查看每次会话，「日报 / 周报」查看自然日和自然周统计。

App 需要用户手动授予特殊访问权限；不使用运行时权限弹窗获取使用统计。

## 构建

标准 Java 17 + Gradle 8.11.1 + AGP 8.9.3，compileSdk / targetSdk 35，WorkManager 2.10.1。

参考 EZip 的本机工具链复用与独立核心测试经验；本项目需要 AndroidX WorkManager，所以使用标准 Gradle，不复制 EZip 的手工打包链或签名材料。

Windows 首次安装官方工具到项目内（`.toolchain` 不提交）：

```powershell
.\tools\bootstrap.ps1 -WithJdk
.\build.ps1
```

如本机需代理，可给上述两条命令添加 `-Proxy http://127.0.0.1:7897`。代理地址不会写进仓库配置。

也可用 Android Studio 打开根目录，选择完整 JDK 17+（需包含 `jlink`），在 `local.properties` 配置 `sdk.dir`，执行：

```powershell
.\gradlew.bat :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

无需 Android SDK 的核心逻辑回归：

```powershell
.\tools\test-core.ps1 -Jdk '<本机 JDK 路径>'
```

构建输出、工具缓存、`local.properties` 与签名材料均在 `.gitignore` 中。正式签名需另行配置自己的密钥；不复用其他项目密钥。

## 工程结构

| 位置 | 职责 |
| --- | --- |
| `core/` | 无 Android 依赖的会话状态机、5 秒合并、精确前台时长、流向聚合、自然日 / 周边界 |
| `app/.../Collector.java` | 授权 / 交互门控、增量事件查询、缺失标记和补报 |
| `app/.../Store.java` | 原子保存游标与会话、7 天清理、只含当前保留源数据的报表 |
| `app/.../TrafficApplication.java` | 唯一每日任务及进程存活时的解锁机会触发 |
| `app/.../MainActivity.java` / `Charts.java` | 中文界面、时长柱状图、定向流向图、时间线与报表 |
| `tools/CoreCheck.java` | 可在电脑独立执行的统计核心回归场景 |

## 重要边界

- **前台使用会话 ≠ 进程生命周期。** PAUSED、锁屏和熄屏用于结束或切分会话；不会声称 App 被杀死。
- **流向 ≠ 用户点击。** 统计相邻不同 App 的前台进入关系，前一 App 离开超过 30 秒不再连接；跨锁屏 / 熄屏 / 重启不连接。分屏时不代表唯一输入焦点。
- **5 秒是会话合并规则，不是轮询频率或实时上报保证。** 合并后的时长由实际前台子区间累加，短暂切走时间不计入。
- 系统只保留「几天」事件，不能保证完整 7 天。WorkManager 每日触发不保证准时；熄屏任务跳过采集，下次打开 / 可交互机会再补。超过 24 小时没拉取会保守标记历史可能不完整。
- 不承诺零功耗：不常驻轮询、不主动在熄屏时唤醒采集，但系统启动 Worker、执行状态判断仍有少量开销。
- 设备可交互且已解锁不等于用户正在触摸，不能识别「亮屏但人没操作」。无屏幕 / 锁屏历史边界时不推断未知使用。
- 公开 SDK 不提供 Activity 实例编号；为避免读取页面类名，使用包级状态和 5 秒合并策略。同包复杂多 Activity / 多窗口场景可能提前结束会话，不能保证精确的 Activity 配对。
- 查询为空不等于零使用；已知空缺明确标记。不从汇总伪造逐次打开 / 关闭时间。关机时间不是可靠关闭时间，未配对结束标记未知。
- 用户撤权、强行停止、厂商后台限制、关机都会影响补采与报表时效。绝不通过精确闹钟 / 前台服务绕过。
- 7 天包含报表的源数据；源数据过期后重新生成聚合，不永久保存历史使用信息。睡眠或应用未执行期间不能到点物理删除；恢复时清理，读取时过滤过期源记录。
- 内部游标、设备交互布尔状态和包级前台标记仅用于去重和断点恢复，不包含页面标识、页面内容或用户输入。App 名称不可解析时显示包名。
